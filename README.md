# シフト給料アプリ

シフトを登録するだけで、給料の見込みを自動計算してくれるWebアプリです。ブラウザで開くだけで動き、データはその端末のブラウザ内（localStorage）に保存されます。

## 概要

- 複数のバイト先を登録でき、バイト先ごとに給与形態（時給・日給・月給）や深夜割増率を設定できます。時給のバイト先では、期間別時給（開始日ごとの時給）と研修期間中の時給も設定できます。
- シフトを入れるたびに給料が自動で計算され、月ごとの合計やバイト先ごとの小計が一目で分かります。
- 深夜をまたぐシフト（例：22:00〜翌2:00）にも対応しています。ダイヤル入力では24時間以上の勤務（最大48時間未満）も入力できます。
- 日付ごとのメモと、自由なメモ帳も付けられます。
- 月ごとにシフト表の画像を貼り付けて保存でき、シフト入力のときに見返せます。PDFファイルの添付や、シフト表ページへのURLリンクの登録もできます。
- 画面は「シフト／バイト先／設定」のタブで切り替える構成です。シフトのタブでは、月の合計のすぐ下にシフト一覧（カレンダー／リスト）が来る並びで、一覧が先に目に入ります。「自分の設定」（名前・スキン・表示設定・バックアップ）と「バイト先の設定」（時給・締日・給料日・交通費など）は、タブで明確に分かれています。
- 「自分の設定」では、スキンのほかに文字の大きさ（小・標準・大）とフォントも選べます。フォントは標準（システム）・ゴシック系・読みやすいゴシック（Noto）・すっきりしたゴシック・丸ゴシック系・丸ゴシック（やわらかい／まるみ強め）・手書き風・明朝系の9種類です（Webフォントを使う選択肢は、読み込めない環境では標準に近い書体で表示されます）。また、高度な機能を隠して大きくシンプルな画面にする「かんたんモード」もあります。
- 写真やPDFから文字を読み取ってシフトの下書きを作る、OCRの実験機能も入っています。
- シフトには区分を付けられ、区分ごとの件数も分かります。区分はバイト先ごとに自由に作れます（初期区分は早番・日勤・遅番・夜勤で、名前・開始・終了・休憩を編集でき、準夜勤・早出・遅出などの追加や削除もできます）。
- 手入力を楽にする機能もあります：期間＋曜日指定の一括作成、週のコピー、シフトの複製、名前付きテンプレート（いつものパターン）の保存と一括適用。
- 「収入まとめ」では、その月の収入合計・バイト先ごとの内訳・先月との比較が見られ、給料が振り込まれたらバイト先ごとに「もらえた」をチェックして、受け取り済み／未受取の金額を確認できます。給与明細の金額を「実際の金額」に入れると計算との差が分かり、交通費やボーナス等の「その他収入」も含めた総合計が見られます。バイト先に天引き率を設定している場合は、天引き額と手取りの目安も表示されます。
- 主な機能の近くには「？」ボタンがあり、タップすると短い説明がポップアップで表示されます。
- 本体は `index.html` の1ファイルだけで完結します（OCR・PDF読み取りのみ、Tesseract.js と PDF.js をCDNから読み込みます）。

## 機能

### バイト先の設定
- 名前・給与形態（時給・日給・月給）・色を登録できます。ジャンル（候補から選択も自由入力も可）・場所・締日（例：月末）・給料日も登録でき、バイト先一覧に表示されます（締日・給料日は記録用で、計算には使いません）。給料日は「日付で指定」（例：翌月25日、当月月末）と「勤務最終日（最終日が終わったら支給）」の2種類から選べます。勤務最終日は、月末払いではなく最終の勤務日が終わったらその場・その日に支給される働き方（巫女バイトなど）向けで、一覧では「給料日 勤務最終日」と表示されます。
- 受け取り方法（振り込み／手渡し）も登録できます。バイト先一覧（「受取 振り込み／受取 手渡し」）と収入まとめのバイト先ごとの行（「受け取り：振り込み／手渡し」）に表示されます。既存のバイト先（項目が無いデータ）は「振り込み」として扱われます。バックアップにも含まれます。
- 天引き率（%）も設定できます。所得税などで何%引かれるかの目安で、収入まとめに天引き額と「手取りの目安」（給料＋交通費−天引き）が表示されます（あくまで概算で、実際の源泉徴収とは異なる場合があります）。
- 給与形態が時給の場合は、時給と深夜割増率（初期値25%）を登録します。
  - 期間別時給：開始日ごとに時給を設定でき（複数登録可）、給与計算では勤務日の時点の時給が適用されます（例：基本の時給¥1,180＋「2026-11-01から¥1,240」→ 10/31のシフトは¥1,180、11/1のシフトは¥1,240）。開始日より前の日は基本の時給です。
  - バイト先一覧などで表示される「今の時給」も、計算と同じルールで今日の時点の時給に自動で入れ替わります。期間別時給の開始日が来ていればその時給（「時給 ¥1,240（期間別時給）」）、研修期間中は研修時給（「時給 ¥1,000（研修時給）」）が表示されます。
  - 期間別時給の入力欄の下には「時給の履歴（期間ごと）」が表示され、過去分も含めて期間ごとに時給を確認できます。期間別時給は「特別時給」として表示され、期間の終わりは次の期間の開始日の前日です（例：基本¥1,180＋2026-11-01から¥1,240 → 「〜2026/10/31まで 時給 ¥1,180」「2026/11/01〜 特別時給 ¥1,240」）。現在の期間の行は太字で表示されます。履歴はフォームの入力内容に連動してその場で更新されます。
  - 研修期間の時給：研修の開始日と、終了日または「開始日から◯日間」と、研修中の時給を設定できます。研修期間内のシフトには研修時給が自動適用され、期間を過ぎたら通常の時給（期間別時給があればそちら）に戻ります。終了日も日数も空の場合は、開始日からずっと研修扱いになります。
  - 時給の優先順位は、研修時給 ＞ 期間別時給 ＞ 基本の時給 です。
- 給与形態が日給の場合は、日給額を登録します。そのバイト先のシフトは、勤務時間の長さによらず1シフト＝日給額で計算します（深夜割増は付けません）。実働時間は労働時間としてそのまま数えます。
- 給与形態が月給の場合は、月給額を登録します。シフトは出勤記録として登録でき、シフト単位の金額は0円として扱い、収入まとめ（と月の合計・バイト先別小計）には、その月にシフトが1件以上ある月だけ、設定した月額をそのバイト先の月収としてそのまま計上します。まとめの行には「月給（時間数によらず固定・シフトは出勤記録）」と表示されます。
- 新項目が無い既存のバイト先データは、従来通り単一時給（時給形態）として扱われます。
- 交通費の方式（1日あたり／1日あたり＋月の上限／月固定額／定期代）と金額も登録できます（詳しくは「交通費」の節）。定期代の方式では出発駅・到着駅の名前も保存できます。
- 追加・編集・削除ができます。
- バイト先ごとに、勤務区分を自由に設定できます。区分名（例：早番・準夜勤・早出・遅出・夜勤A）と開始・終了・休憩（任意）を追加・編集・削除でき、並び順もそのまま選択肢の並びになります。初期区分は早番 6:30〜15:30、日勤 9:30〜18:30、遅番 12:30〜21:30、夜勤 21:30〜翌6:30（休憩の初期値は未設定）で、既存のバイト先には自動で設定されます。区分を削除しても、その区分が付いた既存のシフトはそのまま残ります。

### 自分の設定
- 「自分の名前」を登録できます（例：山田太郎）。カンマ（、）区切りで複数の表記（例：山田太郎、やまだ）も登録できます。
- 「かんたんモード」をONにすると、高度な機能（読み取り（OCR）・期間別時給・研修時給・天引き率・交通費の細かい方式・その他収入・テンプレート・一括作成・週のコピー・月の添付・収入まとめなど）が隠れ、画面は「今月の合計 → 予定（シフト一覧） → カレンダー」の順に並ぶシンプルな表示になります（その月のシフトが6件以上ある場合は、予定のリストが長くなるためカレンダーが予定より先に表示されます）。「シフトを追加」ボタンは今月の合計のすぐ下に固定され、予定とカレンダーが入れ替わっても位置は変わりません。ボタンと文字も大きくなります（文字の大きさ設定と組み合わさります）。シフトの時刻入力は「打ち込み」に固定されます。データには一切触らないので、OFFに戻せば全部元通りになります。設定は保存され、バックアップにも含まれます。
- 表示設定として「文字の大きさ」（小・標準・大）と「フォント（書体）」を選べます。フォントは、標準（システム）・ゴシック系・ゴシック（Noto・読みやすい）・ゴシック（すっきり）・丸ゴシック系・丸ゴシック（やわらかい）・丸ゴシック（まるみ強め）・手書き風・明朝系の9種類です。アプリ全体に反映され、選択は保存されてバックアップにも含まれます。端末に入っている書体を使う選択肢は、端末によっては見た目が変わらない場合があります。Webフォントを使う選択肢（Noto・すっきり・やわらかい・まるみ強め・手書き風）は、フォントを読み込めない環境では標準に近い書体で表示されます（オフライン時は端末の書体になります）。項目が無い既存の設定データは「標準・標準（システム）」として扱われます。
- 「スキン（見た目のテーマ）」でアプリ全体の色合いを切り替えられます。標準（青）／ピンク／紫／緑／ダーク／キュートの6種類があり、CSS変数（アクセント色・背景色・カード色・文字色など）をテーマごとに切り替える方式です。ダイヤルやスライダーの色もスキンに追随します。区分バッジやバイト先の色ドットなど意味のある色は、スキンによらずそのまま表示されます。ダークは暗い背景用に文字とのコントラストを確保した配色です。キュートはパステルピンクとクリーム色基調で、角丸を大きめにし、影を柔らかくした可愛い雰囲気のテーマです。キュートのときだけ、スライダーとダイヤルのつまみ、カレンダーの色ドットがハート形になります（色は従来通りで、形だけが変わります）。選んだスキンは保存され、次回も同じスキンで開きます。バックアップ（自分の設定）にも含まれます。
- OCRの下書き生成で、シフト表の中に登録した名前が見つかった場合、その名前の列（または行）に属するシフトだけを抽出対象にします。名前が見つからない場合は全体を対象にし、その旨が画面に表示されます。未登録の場合は従来通り全体が対象です。

### シフト登録
- 日付・バイト先・開始時刻・終了時刻・休憩時間（分）・メモを登録できます。交通費の方式が「1日あたり／上限」のバイト先では、その日の交通費（初期値はバイト先の1日あたり金額）も登録・変更できます。
- 開始時刻・終了時刻の入力方法は、「打ち込み／スライダー／ダイヤル」の切り替えタブで選べます（選んだ方式だけが表示されます）。切り替えても入力した値は保持され、選んだ方式は保存されて次回も同じ方式で開きます。シフト登録フォームとテンプレートフォームで共通の設定です。
  - 打ち込み：時刻欄に直接入力します。
  - スライダー：15分刻み（0:00〜23:45）のスライダーで入力できます。スライダーの横には現在の時刻が表示されます。
  - ダイヤル：1つのリングに開始（始）と終了（終）の2つのつまみを載せた単一ダイヤルです。つまみをドラッグ／リング上をタップすると、角度に応じた時刻（1周=24時間、15分刻み）が入ります。各つまみはフォーカスして矢印キーでも±15分動かせます。開始から時計回りに終了までの弧が勤務時間で、弧は12時間ごとに色が切り替わるため、「12時間＋6時間＝18時間」のように読み取れます。中心には開始・終了の両時刻と合計の勤務時間が表示されます。
    - 終了のつまみをドラッグして1周を超えると、24時間以上の勤務（最大48時間未満）も入力できます。2周目の弧は色を変えて重ねて描かれ、中心表示にも「翌日」「翌々日」と合計時間が出ます。終了が何日後かは、シフトのデータに日オフセット（endDayOffset）として保存されます。
  - 時刻欄・スライダー・ダイヤルは相互に連動し、区分プリセットで時刻が自動入力されたときや、編集・複製でフォームに値が入ったときも、表示されていない方式を含めて全て追随します。ダイヤルで作った24時間以上のシフトを編集で開いた場合も、日オフセットがダイヤルに復元されます（打ち込み・スライダーは従来通り24時間未満の扱いです）。
- 終了時刻が開始時刻より早い場合は、翌日まで働いたものとして計算します。
- バイト先と区分は、前回登録したときの選択が次回の初期値になります。
- 追加・編集・削除ができます。
- 区分を付けられます（選択肢はそのバイト先に登録した区分／未設定）。バイト先を選んでから区分を選ぶと、そのバイト先のプリセット時刻が開始・終了に自動入力され、休憩が設定されている区分では休憩も入ります（後から変更できます）。区分が無い既存のシフトは「未設定」として扱われます。
- 「複数の日にまとめて作成」をオンにすると、同じ内容を期間＋曜日指定（例：11/16〜11/30の月・木・金）で一括作成できます。作成前に「◯件作成されます」と件数が表示されます。
- シフト一覧の各行にある「複製」ボタンで、そのシフトの内容をフォームに読み込んで別の日付に登録できます（元のシフトは変更されません）。

### 給与計算
- 時給のバイト先：実働時間 ＝ 終了 − 開始 − 休憩 で計算します。適用する時給は勤務日によって決まります（研修時給 ＞ 期間別時給 ＞ 基本の時給。詳しくは「バイト先の設定」の節）。
- 22:00〜翌5:00 は深夜帯として、時給 ×（1 ＋ 割増率）で計算します。
- 休憩時間は、深夜帯以外の時間から先に差し引きます。
- 日給のバイト先：1シフト＝日給額です（時間・深夜帯は関係なし）。月給のバイト先：シフト単位は0円で、月額を別途計上します（詳しくは「バイト先の設定」と「収入まとめと受け取り確認」の節）。
- 金額は円未満を切り捨てます（時給計算の場合）。
- 24時間以上のシフトは、終了の日オフセット（endDayOffset）を使って実働時間を計算します。深夜帯の判定は日ごとに繰り返されるため、2日目以降の深夜帯も正しく割増されます。endDayOffset の無い従来データは0として扱われ、従来通り「終了≦開始なら翌日」として計算されます。

### 月表示
- その月のシフト一覧（日付順）、合計給料見込み、合計労働時間、バイト先ごとの小計を表示します。
- 月の移動には「今月」ボタンがあり、ワンタップで現在の月に戻れます（リスト・カレンダー共通）。
- シフト一覧の上部には、その月の合計（給料見込み・労働時間）が固定表示（sticky）され、一覧をスクロールしても見えます。
- シフト一覧では区分がバッジ表示され、月のまとめに区分ごとの件数も表示されます。
- シフト一覧は「リスト／カレンダー」の表示切り替えができます。選んだ表示は保存されて次回も同じ表示で開きます。
  - カレンダー表示は表示中の月の月グリッド（日曜始まり）です。シフトのある日にはバイト先の色ドット（最大3つ）と、複数件ある日には件数が付き、今日の日付が目立つように表示されます。
  - 日をタップすると、その日のシフト詳細（時刻・区分・金額と編集／複製／削除ボタン）がカレンダーの下に表示されます。前月／翌月ボタンはリスト表示と共通で、カレンダーも連動して切り替わります。
  - 「範囲を選んでまとめて登録」を押すと範囲モードになり、日を2つタップして開始日と終了日を選ぶと（月を切り替えてまたいだ範囲も選べます）、選んだ期間が色付けされます。そのままバイト先・区分・開始・終了・休憩を1回指定して「この範囲に登録」を押すと、期間内の各日に同じシフトを一括登録できます。既に同じシフト（同じ日付・バイト先・開始・終了）がある日は、二重登録を防ぐためスキップされ、件数が結果に表示されます。曜日を選んで登録したい場合は、シフト登録フォームの「複数の日にまとめて登録する（期間＋曜日）」を使ってください。
- 前月・翌月への切り替えができます。
- 「週のコピー」はシフト一覧より下に配置されています。コピー元の週（月曜始まり）にあるシフトを、コピー先の週へまとめてコピーできます。実行前にコピーされる件数と対象期間が表示され、確認ダイアログで了承してからコピーします。コピー先に既にあるシフトは消えず、コピー分が追加されます。

### 収入まとめと受け取り確認
- 表示中の月について、収入合計（給料見込み）を大きく表示し、あわせて労働時間の合計とシフト件数を出します。
- バイト先ごとの内訳（金額・労働時間・件数）も表示します。金額は給与計算（computePay）の結果をそのまま集計したもので、月サマリーの合計と一致します。月給のバイト先は月額がそのまま内訳の金額になり、「月給（時間数によらず固定・シフトは出勤記録）」の表示が付きます。日給のバイト先には「日給（1シフトごとの金額）」の表示が付きます。各バイト先の行には受け取り方法（「受け取り：振り込み／手渡し」）も表示されます。
- 先月との比較も表示します。先月に収入がある場合は「先月より ▲ +¥◯ 多いです／▼ -¥◯ 少ないです（増減率つき）」、先月に収入が無い場合はその旨を表示します。月の切り替えに連動します。
- 受け取り確認：バイト先ごと・月ごとに「もらえた」のチェックを付けられます。チェックの状態は localStorage（キー `shiftPayApp.received`、形式 `{ "YYYY-MM": { workplaceId: true } }`）に保存され、開き直しても復元されます。バックアップ（書き出し／読み込み）にも含まれます。
- チェックを付けたバイト先の分は「受け取り済み」、付けていない分は「まだ受け取っていない」として、金額が分かれて表示されます。チェックの付け外しは表示と状態管理だけで、給料の計算結果そのものは変わりません。
- 実際の金額：バイト先ごと・月ごとに、給与明細の金額（実際に受け取った金額）を手入力できます。入力すると、計算との差額（「計算より +¥◯」「計算より −¥◯」「計算通りです」）が表示されます。差額の基準は「給料見込み＋交通費」です（給与明細は交通費込みで振り込まれることが多いため）。交通費が無いバイト先では給料見込みだけが基準になります。実際の金額を入力すると「もらえた」も自動でチェックされます（金額を空にしてもチェックは外れません）。保存先は localStorage（キー `shiftPayApp.actualPay`、形式 `{ "YYYY-MM": { workplaceId: 金額 } }`）で、バックアップにも含まれます。入力が空の場合は従来通り見込み金額だけの表示で、給料の計算には一切影響しません。「受け取り済み／まだ受け取っていない」の金額は、従来通り給料見込みだけが対象です。
- 天引きと手取りの目安：バイト先に天引き率（%）を設定している場合、バイト先ごとの行に天引き額と「手取りの目安」（給料＋交通費−天引き額）が表示され、内訳にも天引き合計と手取りの目安の合計が出ます。天引き額は（給料＋交通費）×天引き率の四捨五入です。あくまで目安であり、実際の源泉徴収とは異なる場合があります。給料計算そのものには影響しません。
- 見た目はスキン（CSS変数）に追随します。

### 交通費
- バイト先の設定で交通費の方式を選べます。交通費は給与計算（時給計算）には混ぜず、収入まとめに別枠で表示します。バイト先ごとの行には方式が分かるラベル（例：「交通費（1日あたり）」「交通費（定期3か月 ¥15,000の月換算）」）と金額が出て、「給料＋交通費の合計」も分かります。
  - 1日あたり：1日あたり金額×出勤分です。シフトの追加・編集フォームにも交通費の欄があり（初期値はバイト先の1日あたり金額）、その日だけ0円や別金額に変更できます。月の交通費は、各シフトに保存された交通費の合計です。
  - 上限：1日あたりの合計が、設定した月の上限額を超えた分は切り捨てて表示します（上限が0・未設定のときは上限なしとして扱います）。
  - 月固定額：出勤日数によらず、月に固定額を計上します。
  - 定期代：定期の金額と期間（1か月／3か月／6か月）を設定し、金額÷期間の月数を月換算（四捨五入）で計上します（例：3か月定期 ¥15,000 → 月 ¥5,000）。
- 既存シフト（交通費フィールドなし）は、バイト先の1日あたり金額で計算される互換扱いです。編集して保存した時点で、そのシフトの値として固定されます。方式のない既存のバイト先は「1日あたり・0円」として扱います。
- 交通費は、その月にシフトのあるバイト先についてだけ計上します（シフトの無い月は、そのバイト先の交通費も0円です）。
- 定期代の方式では、出発駅・到着駅の名前を保存でき、「定期代を調べる」ボタンで Yahoo!路線情報の検索結果（`https://transit.yahoo.co.jp/search/result?from=駅名&to=駅名`、駅名のみで開ける形式）を新しいタブで開けます。各ルートの「定期券」から1か月・3か月・6か月の定期代を確認し、金額は手で入力する運用です（静的サイトのため自動入力はされません）。駅名はバックアップにも含まれます。

### その他収入
- ボーナスなど、シフトの給料以外の収入を月ごとに複数登録できます（名前・金額。バイト先の指定は任意）。収入まとめの下の「その他収入」欄から、表示中の月に対して追加・削除できます。
- 収入まとめでは、給料・交通費とは分けて「その他収入」を表示し、総合計（給料＋交通費＋その他収入）も表示します。シフトの無い月でも、その他収入と総合計は表示されます。給与計算や「実際の金額」との差額表示には含めません。
- 保存先は localStorage（キー `shiftPayApp.otherIncome`、形式 `{ "YYYY-MM": [{ id, name, amount, workplaceId }] }`）で、バックアップにも含まれます。

### ヘルプ
- 主なセクションや注意書きの近くにある「？」ボタンをタップすると、その機能の短い説明がポップアップ（モーダル）で表示されます。
- 対象は、収入まとめ（もらえたチェック・実際の金額）、給与形態・期間別時給・研修時給、交通費、その他収入、写真から読み取り、切り取り、画像の前処理、シフトの下書き、シフト一覧（カレンダー表示）、時刻の入力方法、区分、メモ帳、スキン、表示設定、かんたんモード、添付（画像・PDF・リンク）、バックアップの17トピックです。
- 閉じる操作は、×ボタン、背景（ポップアップの外側）のタップ、Escapeキーの3通りがあります。

### いつものパターン（テンプレート）
- バイト先・区分・開始・終了・休憩・曜日のセットに名前を付けて保存できます（例：「カフェA 平日・遅番」）。
- パターンを選んで「適用」すると、期間（表示中の月／翌月ボタン、または日付範囲）を指定して、その曜日に当たる日へ一括でシフトを作成できます。作成前に「◯件作成されます」と表示され、確認ダイアログで了承してから作成します。
- 曜日選択には「平日（月〜金）」「全て」のショートカットがあります。
- パターンは編集・削除ができます。区分を選ぶと、そのバイト先のプリセット時刻が自動入力されます。開始・終了時刻にはシフト登録と同じ入力方法の切り替え（打ち込み／スライダー／単一ダイヤル）が付いていて、ダイヤルでは24時間以上のパターンも作れます（日オフセットもパターンに保存され、適用したシフトに引き継がれます）。

### メモ
- 日付メモ：日付ごとに自由なメモを1件残せます。カレンダー表示で日を選ぶと、その日の詳細の下にメモの入力欄があり、シフトのない日にも書けます。メモのある日にはカレンダーに ✎ の印が付きます。リスト表示では、その日のシフト行の上にメモが表示されます。
- メモ帳：「メモ帳」セクションで、タイトル＋本文のメモを複数作れます。一覧は更新日時の新しい順で、編集・削除ができます。
- どちらもブラウザ内に保存され、バックアップ（書き出し／読み込み）にも含まれます。

### シフト表の添付（画像・PDF・リンク）
- 表示中の月ごとに、シフト表の画像（最大3枚）・PDF（最大3件）・URLリンクを保存できます（月を切り替えると、その月の添付が表示されます）。すべてバックアップに含まれます。
- 画像の追加方法は2通りあります。
  - 「画像を追加」ボタンから画像ファイルを選ぶ（スマートフォンでは写真フォルダから選べます）。
  - PCでは、コピーした画像をページ上で貼り付け（Ctrl+V）ても追加できます。
- 保存前に画像は自動で幅最大1200pxにリサイズされ、JPEG形式で圧縮されるため、保存容量を抑えられます。
- サムネイルをタップ／クリックすると大きく表示されます。「削除」ボタンで1枚ずつ削除できます。
- PDFは「PDFを追加」ボタンから選んで添付できます。画像と同じ保存仕組み（ブラウザ内にファイル内容をそのまま保存）を使うため、圧縮されません。大きなファイル（目安：1ファイル2MB超）は追加時に注意が出て、ブラウザの保存容量の都合で保存できない場合はその旨の案内が出ます（保存できなかった分は残りません）。一覧の「開く」からブラウザのビューアで表示でき、「削除」で1件ずつ削除できます。PDFは画像とは別に数えるため、画像の枚数には影響しません。読み取り（OCR）の「保存済みの今月の画像」にもPDFは出ません。
- リンクは、URLと表示名（任意）を登録できます。シフト表のページなどのURLを月ごとに残しておくためのもので、複数登録でき、タップすると新しいタブで開きます。「削除」で1件ずつ削除できます。URLの先頭に https:// が無い場合は自動で補われます。保存先は localStorage（キー `shiftPayApp.monthLinks`、形式 `{ "YYYY-MM": [{ id, url, label }] }`）です。

### 写真から読み取り（OCR・実験）
- シフト表の写真から文字を読み取り、シフトの下書きを自動で作る実験機能です（Tesseract.js を使用、認識言語は日本語＋英語）。
- 画像は、ファイルから選ぶ方法と、保存済みの今月の画像から選ぶ方法のどちらでも指定できます。PDFファイルも選べます。
- 画像を選ぶと「切り取り（任意・写真のみ）」が表示されます。画像の上をドラッグして読み取る範囲を選ぶと、その範囲だけを切り取って読み取れます。自分の名前の列だけを切り取ると、文字が大きくなるため読み取りやすくなります。選んだ範囲は四隅の丸で大きさを変えられ、中のドラッグで移動でき、「切り取りをリセット」で解除できます。切り取りのドラッグ中はページがスクロールしないようになっています。切り取りを設定した状態では、「この範囲で読み取る」でも下の「読み取る」でも、切り取り後の画像だけが読み取り対象になります（全体を読み取りたいときは切り取りをリセットしてください）。切り取らずに全体を読み取ることもできます（PDFには切り取りはありません）。
- 切り取りには「2か所モード」もあります。1か所目（日付の列）と2か所目（自分の名前の列）を別々に選ぶと、2つを横につなげた画像にしてから読み取ります。名前の列だけを切り取ると日付が入らない表でも、日付と対応づけて読み取れます。初期設定は従来の1か所モードです。
- 読み取り前に画像の前処理ができます。強さは「なし／弱め（グレースケール＋コントラストのみ）／強め（適応的二値化）」から選べ、初期設定は「強め」です。前処理をする場合は幅2400pxを上限に最大3倍まで拡大してから処理します。前処理が「なし」の場合でも、小さい画像はOCRの前に拡大（幅1200px未満なら2倍以上）してから読み取るため、小さな文字が認識されやすくなります。強めは、画像の場所ごとの明るさに合わせて二値化する方式（適応的閾値）で、色付きのセル（オレンジや赤の背景に黒文字）に書かれた時刻も消えにくくなります。以前の大域的な二値化では色付きセルの背景まで真っ黒になり中の文字が消えてしまったため、この方式に変えました。前処理後の画像はプレビューで確認できます（写真を選んだときに表示されます）。実際のシフト表写真で「なし／弱め／大域二値化／適応的二値化」を実測比較し、時刻や名前を最も多く拾えた適応的二値化を初期設定にしています。ただし写真によっては「弱め」や「なし」の方が良い場合もあるので、読み取り結果が悪いときは強さを変えて試してください。
- PDFに文字データが入っている場合は、その文字をそのまま使うため、写真より正確に読み取れます。文字データが入っていないPDF（スキャン画像など）は、ページを画像化してOCRで読み取ります（PDF.js を使用）。
- 時間割形式のPDF（最上部のヘッダーに時限ごとの時刻範囲があり、日付×列でセルが埋まる表）は、文字の位置情報から下書きを作ります。ヘッダーの時刻範囲の位置で列を判定し、セルに文字のある列の時刻範囲が下書きになります。月が複数並ぶ表では、表示中の月の側だけが対象です。この形式でないPDFは、従来通りテキストから下書きを作ります。
- 「読み取る」を押すと認識が始まります。初回は言語データをダウンロードするため、進捗（％）が表示され、少し時間がかかります。
- 認識したテキストはその場で修正できます。「下書きを作成」を押すと、テキストから日付と時間のパターンを抽出して下書きを作ります。
  - 対応パターンの例：「11-22.5」（11:00〜22:30）、「11.5-23」（11:30〜23:00）のような開始-終了、「17」のような開始のみ（終了は空欄になるので入力してください）。
  - 小数表記は「時」の小数として扱います（例：22.5 ＝ 22:30）。
  - 日付は、テキスト内の日（1〜31）と表示中の月を組み合わせて作ります。
  - カレンダー形式の表にある漢字1文字（早・日・遅・夜、深は夜勤として扱います）も対象です。日付と漢字の対応が取れたら、その区分のプリセット時刻で下書きを作ります。対応が取れない場合は下書きを作らず、認識テキストの表示に留めます。
- 下書きは行ごとに日付・開始・終了・バイト先・区分・休憩を編集でき、「まとめて登録」でシフトとして一括登録できます。下書きで区分を選ぶと、そのバイト先のプリセット時刻が反映されます。
- テキスト内に時刻の範囲（「9:30-11:00」など）がある場合は、範囲を開始・終了のペアとしてだけ下書きにします。単独でしか拾えない時刻の断片や、日付との対応が曖昧な範囲は、間違った行を作らないため下書きにせず、件数だけ画面に表示します。範囲が無いテキストでは、従来通り開始のみのパターンも下書きになります。
- OCRでコロンが落ちて「830」「1700」のような数字列になった時刻も、時刻として解釈します（3桁＝時1桁＋分2桁、4桁＝時2桁＋分2桁。例：830→8:30、700→7:00、1700→17:00）。「830 1700」のように2つ並んだ場合は開始・終了のペアとして下書きにします。時0〜29・分0〜59の範囲に収まらない数字列や、日付・金額らしい数字（年・月日・円表記など）は時刻として扱いません。
- OCRの下書きは自動で保存され、ページを開き直しても復元されます。
- 「まとめて登録」では、入力が揃っている行だけが登録され、未入力の行は登録されずに下書きに残ります。登録結果（登録できた件数と、残った未入力の行数）は画面内に表示されます。未入力の欄（日付・開始・終了・バイト先）は赤い枠で目立つように表示され、入力するとその場で枠が消えます。
- 二重登録の防止のため、既に同じシフト（同じ日付・バイト先・開始・終了）が登録されている行はスキップされ、「同じシフトが既にあるため◯件スキップしました」と画面に表示されます。登録できた行は下書きから取り除かれます。また、登録が完了したあとは「まとめて登録」ボタンが無効化され、下書きの内容を変更する（編集・削除・作り直し）まで連打しても再登録できません。
- 「直前の登録を取り消す」ボタンで、直前の「まとめて登録」で登録した分をまとめて削除できます（ページを開いている間だけ有効です）。
- 「下書きをすべて削除」ボタンで、下書きを一括で消せます（確認ダイアログが出ます。登録済みのシフトは消えません）。
- 曜日はOCRで読んだ文字を信用せず、日付から実際のカレンダーで計算して使います。下書きの行には日付の横に曜日が表示され、日付を変えると曜日も自動で直ります。
- 下書きを作る際、読み取り間違いを推測で補正します。補正した行は黙って直さず、元の読み取り値と推測後の値を並べて表示し、「推測が合っています」と確認するか、自分で欄を直すまで登録されません（未確認の行は「まとめて登録」の対象から外れます）。補正の種類は3つです。
  - 最頻ペア補正：その表で最も多い開始・終了の組（最頻ペア）を求め、片方が最頻と一致し、もう片方が最頻の「桁落ち」（例：終了が 7:00 と読まれたが最頻は 17:00）である行を、最頻ペアに合わせて直します。大きく違う行は補正しません。最頻ペアが2件未満、または同数1位が複数ある場合は補正しません。
  - 終了時刻の推測補修：終了が開始以下になり、深夜跨ぎとして解釈しても勤務時間が不自然に長くなる行は、誤読の値が多数派で最頻ペア補正が効かない場合でも、終了に「1」を補う／12時間足した値のうち、その表で実際に現れる終了時刻（2回以上）と一致するものが1つだけあれば、その値に直します（例：8:30開始で終了が「700」と読まれた行を、その表で多い17:00と判断）。深夜跨ぎが正当な行（22:00〜2:00など）は補修しません。
  - 日付の連番補修：行が日付の昇順に並んだ表では、正しく読めた日付を手がかりに、「221」（12/21のスラッシュ落ち）のように文字化けした日付行を前後の連番から推定して補います。曜日の読み取りが推定した日付と食い違う区間や、確信が持てない行は補いません（休みの日の行も連番の位置合わせに使われます）。
- 漢字カレンダーで区分（早・日・遅・夜）が取れた行は、そのバイト先のプリセット時刻で開始・終了が自動で埋まります。
- 「自分の設定」で名前を登録している場合、表の中のその名前の列だけを抽出対象にします（単語の位置情報が使える場合）。名前が見つからない場合は全体を対象にし、その旨が表示されます。
- 注意：実験機能のため読み取り間違いがあります。必ず確認・修正してから登録してください。画像はブラウザの中で処理され、外部に送信されません（ライブラリと言語データのダウンロードのみ通信します）。

## 使い方

1. `index.html` をブラウザで開きます。
2. 「バイト先」タブから、バイト先の名前と時給を登録します。
3. 「シフト」タブの「シフトを追加」からシフトを登録すると、給料が自動計算されます。
4. 上部の ◀ ▶ で月を切り替えて、月ごとの合計を確認できます。
5. シフト表の画像・PDF・リンクがある場合は、「シフト表の画像・PDF・リンク」からその月の添付を追加しておくと、入力のときに見返せます。
6. 「写真から読み取り（実験）」では、シフト表の写真を選んで「読み取る」→「下書きを作成」と進めると、シフトの下書きが作れます。内容を確認・修正してから「まとめて登録」してください。

## データについて

データ（バイト先・シフト・区分プリセット・自分の設定・画像・PDF・月のリンク・OCRの下書き・いつものパターン・日付メモ・メモ帳・受け取り確認・実際の金額・その他収入）はブラウザの localStorage に保存され、ページを開き直しても復元されます。別の端末や別のブラウザとは共有されません。ブラウザのデータを消去すると登録内容も消えるのでご注意ください。画像は圧縮して保存されますが、PDFはそのまま保存され、容量には上限があるため、不要になった古い月の画像やPDFは削除してください。

「自分の設定」にはデータのバックアップ機能があります。「データを書き出し（JSON）」で全データ（バイト先の新項目＝給与形態・ジャンル・場所・締日・給料日・給料日の種類・受け取り方法・天引き率・期間別時給・研修設定・日給額・月給額を含む。画像・PDF・月のリンク・下書き・パターン・日付メモ・メモ帳・受け取り確認・実際の金額・その他収入、自分の設定＝名前・スキン・文字の大きさ・フォント・かんたんモードも含む）をファイルに保存でき、「データを読み込み（JSON）」で確認のうえ現在のデータと置き換えて復元できます。

「バイト先だけを読み込み（JSON）」という部分インポートもあります。バックアップファイルの中のバイト先だけを取り込むもので、IDが同じバイト先は読み込んだ内容で上書きし、IDが新しいバイト先は追加します。シフト・設定・メモなど他のデータは一切変更しません（別のアプリやブラウザで作ったバイト先設定だけを持ってきたいときに使えます）。

注意：LINEなどのアプリ内ブラウザで開くとデータが消えやすくなります。Safariで開いて「ホーム画面に追加」しておくとデータが残りやすくなります。別のブラウザで開くと別のデータになります。大事なデータは、ときどき書き出してバックアップしてください。

## 動作環境

モダンブラウザ（スマートフォン・PC両対応）。基本機能はインターネット接続なしで使えますが、OCR・PDF読み取りを使うときだけ、ライブラリ（Tesseract.js／PDF.js）と言語データのダウンロードのためインターネット接続が必要です。

## 将来の移行・統合計画

このアプリの今後の方向性です。いずれも計画段階の話で、実装時期は未定です。

### 現在の構成

- 本体は静的なHTMLファイル1つで、GitHub Pages で公開しています。サーバー側のプログラムはありません。
- データはブラウザ内の localStorage に保存します。そのため、アカウント登録なしですぐ使える一方で、ログイン機能はなく、別の端末や別のブラウザとデータを共有（同期）することはできません。ブラウザのデータを消去すると登録内容も消えます。

### ログイン・端末間同期への移行（Firebase）

- 将来的には、Firebase（Authentication ＋ クラウド保存）へ移行し、メールアドレスとパスワードでログインして、複数の端末で同じデータを使えるようにする計画です。
- パスワードは Firebase Authentication が管理する想定で、このアプリ自体がパスワードを保存することはありません。
- 移行は、現在の公開版とは別の試作版で検証してから進める予定です。現在のデータは、バックアップ機能の書き出し（JSON）を使って引き継げるようにする想定です。

### 2つの版の統合

- このアプリには現在、Museアプリ版（データはサーバー側に保存され、写真を送ると読み取り登録までできる版）と、このGitHub版（ブラウザ内保存の版）の2系統があります。
- 将来的には、機能と保存の仕組みを1つの版に統合していく方向で考えています。どちらの形に寄せるかは、ログイン版の試作の結果を見て決めます。

### 移行後に実装する機能

- 定期代のアプリ内表示のように、外部サービスの情報をサーバー側で取得・処理する必要のある機能は、静的なHTMLだけでは実現が難しいため、移行後に実装する計画です（現在は、定期代を調べるための外部サイトへのリンクボタンのみ用意しています）。
